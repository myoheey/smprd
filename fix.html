수정 요청의 3원칙

원칙 1
한 번에 하나만

여러 개를 한꺼번에 고치면 잘 되던 기능이 깨지기 쉬움

원칙 2
저장하고 고치기

잘 되는 버전을 HTML로 저장한 뒤 다음 수정 요청

원칙 3
구체적으로

어디를, 무엇을, 어떻게 바꿀지 + 바꾸지 말 것

이 자료의 예시는 모두 예시 앱 「기억 이론 인출 퀴즈 튜터」를 기준으로 함. [대괄호] 부분을 본인 앱에 맞게 바꿔서 사용함.

1버그를 설명하는 법

AI는 내 화면을 보지 못함. "안 돼"만으로는 무엇이 문제인지 알 수 없어서 엉뚱한 곳을 고치게 됨. 아래 세 가지를 꼭 넣어서 설명함.

① 무엇을 했더니

어떤 화면에서, 무엇을 눌렀거나 입력했는지

② 기대한 결과

원래는 어떻게 되어야 했는지

③ 실제 결과

실제로 어떻게 됐는지 (오류 메시지가 있으면 그대로 복사)

이렇게 말하면
제출 버튼이 안 돼.
이렇게 바꿔 말하기
답을 20자 정도 썼는데 "답 제출하고 피드백 보기" 버튼이 회색으로 남아서 눌리지 않아. 15자 이상 쓰면 눌려야 하는데, 붙여넣기로 입력했을 때만 이래.
왜? "붙여넣기로 입력했을 때만"이라는 조건이 있어야 AI가 입력 감지 부분을 정확히 찾아 고칠 수 있음.
이렇게 말하면
두 번째 세트가 이상해.
이렇게 바꿔 말하기
첫 세트에서 "다시 풀기"를 2개 체크했는데, 두 번째 세트 첫 문제에 "다시 풀기" 표시가 없고 새 문제만 나와. 체크한 개념이 먼저 나와야 해.
왜? 무엇을 체크했고 몇 개였는지 알려 주면 AI가 같은 상황을 재현해서 확인할 수 있음.
버그 수정 요청
앱에 버그가 있어. 원인을 먼저 설명한 뒤 고쳐 줘.

① 무엇을 했더니: [예: 세트 결과 화면에서 "다음 세트 시작"을 눌렀더니]
② 기대한 결과: [예: 다시 풀기로 체크한 문제가 먼저 나와야 함]
③ 실제 결과: [예: 새 문제만 나옴]
오류 메시지: [있으면 붙여 넣기, 없으면 "없음"]

이 버그와 관계없는 부분은 바꾸지 마.

오류 메시지를 찾는 법

  • Gemini Canvas: 오른쪽 위 "콘솔 표시"에서 빨간 글씨를 복사함.
  • 브라우저에서 HTML 파일을 연 경우: F12(맥은 Cmd+Option+I) → Console 탭의 빨간 글씨를 복사함.

2기능 하나 추가하기

새 기능을 넣기 전에 PRD부터 확인함. PRD의 금지 사항과 충돌하는 기능은 넣지 않거나, PRD를 먼저 고친 뒤 넣음.

이렇게 말하면
진도 저장도 되게 하고, 힌트 버튼도 넣고, 오답 노트도 만들어 줘.
이렇게 바꿔 말하기
진도 저장 기능 하나만 추가해 줘. (힌트와 오답 노트는 다음에 하나씩 요청)
왜? 세 가지를 한 번에 요청하면 어느 하나가 안 될 때 원인을 찾기 어렵고, 기존 기능도 같이 깨지기 쉬움.
진도 저장 추가
새로고침하거나 파일을 다시 열어도 아래 정보가 유지되도록 브라우저 저장(localStorage)을 추가해 줘.
- 세트 번호
- 다음 세트에서 다시 풀 문제 목록
- 이미 나온 문제 목록
"처음부터 다시"를 누르면 저장된 정보도 지워지게 해 줘.
다른 기능과 화면 디자인은 바꾸지 마.
확신도 표시 추가
피드백 화면에서 "다시 풀기" 체크 위에 확신도 버튼 3개를 추가해 줘: 확실함 / 애매함 / 몰랐음.
- "애매함"이나 "몰랐음"을 고르면 다시 풀기가 자동으로 체크되게 해 줘.
- 세트 결과 화면에 문제별로 내가 고른 확신도를 같이 보여 줘.
다른 기능은 바꾸지 마.
내 강의자료로 문제 만들기
첨부한 [과목명] 강의자료를 바탕으로, 앱의 QUESTIONS 형식에 맞는 문제 [5]개를 만들어 줘.
- 두 개념의 차이를 설명하게 하는 문제로 만든다.
- 문제마다 핵심 요소 3개와, 각 요소를 판단할 키워드를 넣는다.
- 자료에 없는 내용은 넣지 않는다.
- source에는 근거가 된 슬라이드 번호나 쪽수를 적는다.
만든 문제는 코드 전체가 아니라 QUESTIONS 부분만 보여 줘.

PRD와 충돌하는 요청의 예

이렇게 말하면
답 쓰기 전에 볼 수 있는 힌트 버튼을 추가해 줘.
이렇게 바꿔 말하기
먼저 PRD를 확인함 → 금지 사항에 "답하기 전에 정답이나 힌트를 먼저 보여주지 않는다"가 있음 → 힌트가 꼭 필요하다면 "답을 한 번 제출한 뒤에만 힌트를 보여 주고 다시 쓰게" 하는 방식으로 PRD를 고친 뒤 요청함.
왜? 앱을 고치다 보면 원래 목표에서 멀어지기 쉬움. PRD는 "무엇을 만들지"뿐 아니라 "무엇을 만들지 않을지"를 지켜 주는 기준임.

3디자인 바꾸기

디자인 요청은 "느낌"이 아니라 "대상과 값"으로 말함. 그리고 기능과 문구는 그대로 두라고 꼭 덧붙임.

이렇게 말하면
좀 더 예쁘게 해 줘.
이렇게 바꿔 말하기
기능과 문구는 그대로 두고, 버튼과 제목 색만 진한 초록 계열로 바꿔 줘. 문제 글자 크기는 지금보다 한 단계 키워 줘.
왜? "예쁘게"는 사람마다 다르게 해석함. AI가 레이아웃 전체를 바꾸면서 기능까지 건드릴 수 있음.
디자인 바꾸기 예시
[기능과 문구는 그대로 두고] 아래 디자인만 바꿔 줘.
- 기본 색: [예: 진한 초록 계열]
- 글자 크기: [예: 문제 문장을 지금보다 크게]
- 다크 모드: [예: 기기 설정이 다크 모드면 자동으로 어두운 화면]
휴대폰 화면에서도 글자가 잘리지 않는지 확인해 줘.

4다른 과목으로 옮기기

예시 앱은 문제 데이터(QUESTIONS)와 기능 코드가 분리되어 있음. 구조는 두고 데이터만 바꾸면 다른 과목 앱이 됨.

과목 바꾸기
이 앱의 기능과 화면 구조는 그대로 두고, 내용만 [새 과목명]으로 바꿔 줘.
- 첨부한 강의자료를 근거로 QUESTIONS를 새로 만든다. (문제 [10]개)
- 맨 위 과목명과 주차 표시도 바꾼다.
- 자료에 없는 내용은 넣지 않는다.

예시 앱의 코드가 필요하면 예시 앱 HTML 내려받기.

5꼬였을 때 되돌리기

수정을 거듭하다 보면 앱이 꼬이는 순간이 반드시 옴. 이때 계속 고쳐 달라고 하기보다 잘 되던 버전으로 돌아가는 게 빠름.

이런 상황이렇게 하기
고칠수록 더 이상해짐저장해 둔 마지막 HTML 파일을 다시 붙여 넣고, 아래 "다시 시작" 프롬프트 사용
코드가 중간에 끊김"파일 전체를 처음부터 끝까지 다시 출력해 줘"라고 요청 ("이어서 써 줘"는 앞뒤가 어긋나기 쉬움)
같은 버그를 3번 넘게 못 고침새 대화창을 열고, 저장한 HTML 파일과 PRD를 함께 주고 처음부터 설명
어디서 망가졌는지 모름"방금 수정에서 바꾼 부분만 목록으로 보여 줘"라고 요청해 변경 내용부터 확인
잘 되던 버전에서 다시 시작
아래 코드가 마지막으로 잘 작동하던 버전이야. 이 버전에서부터 다시 시작하자.
이번에 하고 싶은 수정은 [한 가지]야.
이 수정과 관계없는 부분은 한 줄도 바꾸지 마.

[저장해 둔 HTML 코드 전체 붙여 넣기]
